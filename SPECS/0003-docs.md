# SPEC 0003 — README + architecture docs + CONTRIBUTING/SECURITY

- **Ticket:** issuedb #5

## EARS requirements

1. The repository shall provide a concise README stating what the service is (authorization-only RBAC over HTTP), a runnable quickstart, key concepts, and links to deeper docs.
2. The repository shall provide `docs/ARCHITECTURE.md` describing components, the request lifecycle, the data model, the permission-check flow, the key-rotation flow, and deployment topology, with diagrams (Mermaid).
3. The repository shall provide `CONTRIBUTING.md` covering local setup, running the sqlite + postgres test suites, lint/type-check, CI, and the migration policy.
4. The repository shall provide `SECURITY.md` summarizing the security model and how to report issues.
5. The repository shall have a `LICENSE` file matching the declared MIT license.

## Deliverables

- `README.md` — rewritten short (~100 lines): what it is, quickstart (curl + client), gotchas, a Documentation table linking the live API reference + the docs below, when-to-use, dev commands.
- `docs/ARCHITECTURE.md` — Mermaid diagrams: model, components, request-lifecycle sequence, data-model ER, permission-check flow, key-rotation sequence, deployment topology; plus the auditing/transactions and encryption notes.
- `CONTRIBUTING.md` — setup, the `make` gates, CI jobs, coding standards (tenant scoping, secrets, fail-closed, atomic audit), test philosophy, migrations (migretti).
- `SECURITY.md` — reporting, security model, threat notes.
- `LICENSE` — already present (MIT, © 2015 Farshid Ashouri); referenced from README.

Diagrams use Mermaid (GitHub-native, versioned) rather than external image URLs, so
they render on GitHub and stay in sync with the repo.
